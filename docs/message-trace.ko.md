# 메시지 추적

한국어 | [English](message-trace.md)

메시지 추적은 하나의 정확한 `JMSMessageID`와 연관된 지원 범위의 Store 증거를 모아 보여주는 읽기 전용 조사 흐름입니다. 중복 전달, 재전달 또는 장애 원인을 자동 판정하지 않습니다.

![하나의 정확한 JMSMessageID를 조회한 메시지 추적 화면](screenshots/ko/message-trace.png)

## 식별 규칙

- 앞뒤 공백만 제거합니다.
- 남은 `JMSMessageID` 전체가 대소문자까지 정확히 같아야 합니다.
- `ID:ABC:1`과 `ID:ABC:10`은 다른 식별자입니다.
- 파싱된 ID, 원문에서 정확히 관찰된 ID, 패턴 후보는 각각의 증거 신뢰 수준을 유지합니다.

## 검색 범위와 결과 읽기

현재 Store, 열린 모든 Store 또는 직접 선택한 Store를 검색할 수 있습니다. 여러 Store를 검색해도 레코드를 하나의 수명주기처럼 합치지 않습니다. 결과는 Store별, 그 안에서는 journal별로 분리하며 offset 순서는 같은 journal 안에서만 사용합니다.

메시지 상세, 스냅샷 비교의 Message ID, 증거 타임라인의 Message ID와 조사 케이스의 메시지 고정 항목에서 바로 추적으로 이동할 수 있습니다. 결과의 **케이스에서 선택**을 누르면 해당 Store의 조사 케이스로 이동해 한 증거를 선택한 뒤 고정할 수 있습니다. Evidence Bundle 화면에 같은 ID를 입력하면 중앙 비식별 처리 정책을 거친 추적 요약을 ZIP에 포함합니다.

## 해석 한계

반복 ADD는 Consumer 중복 전달을 증명하지 않습니다. ACK/remove가 보이지 않는다는 사실은 메시지가 승인되지 않았음을 증명하지 않습니다. 애플리케이션 처리 성공, 브로커의 현재 Queue 상태, 재전달의 정확한 원인과 장애의 근본 원인도 이 결과만으로 확정하지 않습니다.

## Read-only and lifecycle invariants

- Explicitly opening a Store computes a content-derived SHA-256 chain over normalized relative paths, exact file sizes, and every source byte. The identity Worker reads at most 4 MiB per slice; directory display names and mutable timestamps are excluded.
- The open-time identity is retained with the session and reused by normal tab, filter, sort, and view interactions. It is not recomputed for each interaction. Separate fixture/CI tests still compare source hashes before and after scanning; the general-purpose UI does not expose a before/after whole-Store integrity action.
- Scan cache and File System permission are independent. Cached analysis, comparison, case work, and derived-evidence export remain available without source permission; source-dependent rescanning does not.
- Closing or replacing a session invalidates its generation before a delayed callback can update UI or cache. Its Worker, `AbortController`, listener, timer, and object URL resources are released.
- Writes to the scan-result cache are serialized by Store signature and accept only the currently reserved generation.
- The IndexedDB schema version is 4. A v0.2-era scan/workbench cache is invalidated during migration while incident cases are preserved.
- The scanner and workbench do not connect to a broker, start recovery, compact, rename, delete, or modify selected Store files.

## Export security boundary

The centralized sanitizer is applied to structured fields and nested free text used by JSON, HTML, filenames, notes, comparison values, raw strings, and hexadecimal ASCII representations. Tests use independent canaries for those locations and inspect every ZIP entry plus the complete archive bytes.

The export path serializes in bounded chunks in a Worker, reports monotonic progress, accepts cancellation, and uses a neutral download filename. The current regression tests include a 5,000-record completion budget, immediate cancellation of a 50,000-record case, the actual Worker protocol, stale-operation invalidation, object-URL cleanup, and HTML escaping when redaction is disabled.

The bundle excludes selected Store source bytes. It includes a manifest and per-entry SHA-256 values, and the bundle result reports its own SHA-256. Operators must still inspect an export before sharing it.

## Portable cache and update boundary

Portable cache validation fails closed on malformed manifests, unmanifested entries, mismatched sizes/hashes, unsafe paths, and unsupported cache metadata. It isolates cache keys across application versions, self-heals a corrupt cache, and serializes concurrent cold extraction without publishing partial output.

The update client checks a fixed GitHub Releases endpoint on UI load and does not download assets until an explicit button click. It does not send Store paths, Store names, source bytes, analysis results, or case notes. Automatic replacement is limited to the Windows x64 portable executable.

The replacement implementation repeats trusted metadata lookup server-side; restricts release, asset, and final redirect locations; enforces size and SHA-256 metadata; stages beside the current executable; checks the staged hash again in the helper; verifies the new `--version`; restarts the verified new executable; restores and restarts the previous executable on failure; and cleans task-owned residue. This does not replace operating-system code signing and does not protect against compromise of the release account/channel itself.

## Known limitations

- OpenWire message bodies and page-file indexes are not decoded.
- Journal evidence alone cannot prove current pending/acknowledged state or causal order.
- Records from different journals do not receive an invented global ordering.
- Opening a Store computes a content-derived identity by reading every selected file in bounded Worker chunks. This is an explicit open-time I/O cost; ordinary UI interactions reuse the stored signature.
- Cached analysis may contain operational identifiers even though original Store files are not cached.
- Redaction cannot guarantee recognition of every sensitive value.
- Automatic in-place update is Windows x64 portable only and binaries are unsigned.
- Broker fixture validation covers the documented cases and listed versions, not every ActiveMQ release, OpenWire payload, page index, corruption, recovery, or compaction path.

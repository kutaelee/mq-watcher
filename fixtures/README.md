# MQ Watcher fixtures

The files under `synthetic/` are deliberately small regression inputs for the
read-only evidence scanner.

> **Synthetic fixture != real ActiveMQ-generated store.** Both kinds are kept separate.

They exercise filenames, printable strings, malformed bytes, truncation,
scanner limits, and a generated KahaDB framing conformance case. They must not
be cited as proof that MQ Watcher parses a real broker-produced KahaDB store.
The conformance bytes follow source-level batch, record, and command-envelope
rules, but remain synthetic.

`broker/<version>/` contains KahaDB stores generated by real embedded Apache
ActiveMQ Classic brokers. Each manifest records the exact Maven Central artifact
URL and checksums, Java runtime requirement, broker settings, scenarios, and
fixture-file SHA-256 values. The generated data contains only controlled public
fixture values and uses `fixture-*` IDs instead of workstation hostnames.

`expected/` contains deterministic, reviewed scanner output. Volatile fields
such as scan time, file mtime, and directory signature are intentionally
excluded from the golden comparison.

Generate the committed synthetic byte fixtures with:

```bash
npm run fixtures:generate
```

Validate all fixtures and the source hash invariant with:

```bash
npm run test:fixtures
npm run test:broker-fixtures
```

CI also regenerates each broker fixture from the pinned official artifacts and
runs the same invariant verifier against the fresh store. ActiveMQ is licensed
under the Apache License 2.0; no broker JAR is committed to this repository.

Fixture rules:

- no customer, production, personal, or credential data;
- no broker startup or broker connection;
- no store recovery, compaction, rename, delete, or write during scanning;
- changes to a golden result require review of both the fixture bytes and the
  scanner behavior.
